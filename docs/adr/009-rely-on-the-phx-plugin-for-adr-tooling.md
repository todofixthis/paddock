# 009: Rely on the phx Plugin for ADR Tooling

## Context

[ADR 002][] replaced ADR frontmatter's `tags` with `scope` and ported a generator from
[`todofixthis/class-registry`][class-registry] to validate it:
`scripts/adr/generate_index.py`, parsing frontmatter with PyYAML. An `adr_index`
autohooks pre-commit hook ran it whenever a commit staged an ADR: it regenerated and
staged the index, and blocked the commit on any fault. CI never ran it against the
corpus.

[`phx:writing-adrs`][] now ships its own stdlib tool, [`adr.py`][], beside the skill. It
indexes, validates, scaffolds, supersedes, discharges and renumbers ADRs, and answers
which decisions bind a path. The phx plugin's hooks call it in Claude Code sessions:
they inject the decisions binding a file the first time a session touches it,
regenerate the index after a file-tool edit to an ADR, and report faults. They report
only; none blocks. The tool also installs as a `phx-adr` command, so CI can run it.

The two cannot run side by side. Each writes `docs/adr/INDEX.md` in its own format, so
`adr.py check` reports the repo generator's index as stale. And the plugin's hooks stay
silent unless the index's first line names `phx:writing-adrs`, which the repo
generator's header didn't, so in paddock they never ran.

The maintainer has made the phx plugin canonical for ADR tooling, and
[`.claude/settings.json`][] enables it for Claude Code sessions in this repository.
Every ADR here so far was committed with a Claude co-author.

## Options

Options 2, 3 and 4 all drop the repo generator for `adr.py`'s index format and
numbering, and so share the migration; it does not rank them.

### Option 1: Do nothing

**Pros:** The pre-commit hook blocks a faulty commit for every committer.
**Cons:** The phx plugin's hooks stay off, and `adr.py` can't be used here without
fighting the repo generator over the index. The repo generator is a port that has to
be kept in step with the skill by hand.

### Option 2: The plugin's tool in sessions and in CI (Accepted)

Delete the repo tooling. Sessions get the plugin's hooks; a CI job runs `phx-adr check`
from the plugin at a pinned release's commit.

**Cons:** No local check blocks a commit; a fault from outside Claude Code is caught
only once pushed. Outside Claude Code nothing allocates a number or regenerates the
index, so the author runs `phx-adr` by hand. The pinned ref has to be bumped by hand.
**Risks:** Sessions load whatever plugin release is installed, not the pinned one. A
release that changes the index format leaves CI reporting the index stale right after
a session regenerates it, until the pin catches up.

### Option 3: The plugin's hooks alone

**Pros:** Nothing to pin.
**Cons:** Nothing outside a Claude Code session with the plugin checks the corpus, and
the hooks only report, so a fault from any other commit lands on `main` unnoticed. A
commit that rewrites the index's header line turns the hooks off without a report.

### Option 4: Vendor `adr.py` into the repository

**Pros:** A pre-commit hook could block faulty commits again, plugin or not.
**Cons:** A copy that drifts from the plugin, the maintenance cost Options 2 and 3
remove.

## Decision

Option 2. It keeps one implementation of the conventions, maintained with the skill
that states them, and follows paddock's pattern of backing every local check with CI
(ADR 008, and the jobs in `.github/workflows/build.yml`). Option 3 would make ADRs the
one check here that a commit made outside Claude Code skips entirely.

ADR frontmatter keeps ADR 002's convention, now owned by the skill rather than restated
here: `scope` names the paths a decision binds, never `tags`.

## Consequences

- `docs/adr/INDEX.md` is generated by `adr.py` in the skill's format, which switches the
  plugin's hooks on here.
- ADR filenames and headings use three-digit numbers (`001`), the width `adr.py new`
  allocates, so the four-digit ADRs were renamed and every reference to them updated
  rather than leave the directory mixed.
- `scripts/adr/`, its tests, the `adr_index` hook, and PyYAML and its type stubs (the
  generator was their only user) are removed.
- The CI `adrs` job and `AGENTS.md`'s `phx-adr` commands pin the 8.0.0 release's
  commit. Bump both when sessions move to a new plugin release, and fix whatever the
  new release reports in the same change.
- Bringing the corpus up to the skill's conventions also retitled ADRs 003 and 004 to
  the imperative, corrected the scopes of 001, 003, 004 and 005, and replaced inline
  links with reference-style ones, and trimmed rationale each ADR already stated
  elsewhere. No decision changed.
- The plugin is Claude Code's, so an agent in another harness gets no session hooks,
  and meets the conventions only through `AGENTS.md`, the skill and CI.
